# Overview

The interface is plain inline CSS inside the single HTML file; there is no stylesheet, framework or theme build. It is a fixed dark UI drawn over the graph canvas. Because the CSS ships with the code, this concept is where the visual language is kept current when the interface changes.[^source]

# Theme

One dark theme, defined as CSS custom properties on `:root`: a page background, two panel surfaces, a line colour, text and muted text, and an accent. Node colours (directories, index files, files, tag hubs and concept types) are separate constants in the script. There is no light theme and no theme switch.[^source]

# Layout

- A full-viewport canvas holds the graph.
- A floating top bar holds pill-shaped groups: the title and stats, file actions, view and toggle actions, and directory navigation. It is one transparent layer that never takes the pointer, so a press landing between its groups reaches the graph underneath; only the groups handle a press, each a translucent pill (the panel colour behind a blur), and the load spinner is its own pointer-less pill at the far right. On desktop the bar's right edge and the spinner pull in past an open panel, and below 760px the bar becomes a column with the directory navigation leading and the other groups hidden behind the hamburger. See the [heads-up bar illustration](attachments/hud.svg).
- The **About panel** opens as the startup panel and stays until the user interacts with the interface outside it (a pointer press, a scroll or a keypress outside it dismisses it; the title toggles it and the panel's own controls stay usable). On small screens the startup open is **collapsed** to the banner, the revision, the **Language** picker and the links, with a narrow **chevron** toggle in the middle that reveals the description, the usage list and the AI note and is then removed; opening the panel again from the title shows everything. Shown in full there, the panel **sizes to its text** — it is not capped to a share of the viewport — so the whole text is read at once without a scrollbar whenever the window has the room; only when the window is too short for it is the panel capped to the remaining height and its body scrolls. The **Runtime internals** link sits at the right of the **Source on GitHub** link and uses the Directory colour (the same colour as a Directory node), the **AI transparency** link uses the File colour (the same colour as a File node), and the **Language** picker sits with those links, uses the Directory colour (the same colour as a Directory node), and opens a searchable dialog of every language, grouped by geographic region. It opens the synthetic [`.runtime` directory](../interface/runtime.md) that describes the running viewer. A failed bundle load is reported on the generated [`.runtime/errors.md`](../interface/runtime.md) page rather than in a dialog, while **Open folder…** and **Reload** stay available in the toolbar.
- A filter sidebar docks right, the legend docks left, and the preview and loading overlays sit above the canvas. The **deck of cards** is an optional floating stack of small page cards with no panel of its own: the cards overlap to a header strip, hovering one repels its neighbours to reveal it partly, and each card renders its page as a lazy screenshot; guides can be added as sub-decks. It docks to the left of the filter sidebar when that panel is open, and the filter sidebar sits above the deck — as does the legend panel on small screens — so neither panel is covered; the node tooltip is drawn above the deck but below those panels. Opening a card reads the whole deck as one **continuous stream**, fullscreen within the browser window — with a shared top bar following what is in view. Under a right-to-left interface language the docks mirror to the opposite edge. See [Deck of cards](deck.md) and [Languages](../interface/languages.md).
- The legend lists each node kind and concept type with a colour swatch and count. Clicking a row filters the graph to that group and greys the other rows without removing them, so clicks combine additively and clicking again clears one. Hovering a row highlights that group with the same cue used when hovering a node; while a filter is active the hover adds the hovered group to the selection instead of replacing it, so the standing selection and the hovered group are highlighted together. The list is rebuilt when a directory is entered or a tag filter changes, dropping selections whose group is no longer present.
- Below 760px the bar stacks vertically, the extra groups collapse behind a hamburger, and the side panels dock and slide behind tabs.[^source]

# Components

Shared styling keeps the controls consistent:[^source]

- The controls share one **vocabulary**: one surface (`panel-2`) and one border (`line`) for buttons, fields and lists; hover promotes the border to the accent, focus shows the app's own accent ring, and state is carried by an ARIA attribute rather than a colour. See the [control vocabulary illustration](attachments/controls.svg).
- Marks are **drawn, not imported**: there is no icon font, sprite sheet or image file. A **drawn mark** is an inline `<svg>` or a `<symbol>` reused with `<use>` on a 24×24 grid — the speaker (the audio toggle and the volume), the microphone, the settings sliders, the context ring, the replay arrow and the stop square — and a **type mark** is a character the interface already has (`☰` `▾` `▸` `‹` `›` `⋮` `×` `＋` `✓` `▶` `❚❚` `↑` `↓` `◎` `●` `↗`). A drawn mark uses `currentColor`, so it is muted when idle, the text colour in use and the accent when on or hovered, while a mark that removes reddens to `#e0575b` instead. The token arrows and the context ring animate a **fill** rather than a colour: an accent copy grows through a `clip-path`, and the ring sweeps an accent arc around its muted track. See the [iconography illustration](attachments/icons.svg).
- Buttons share one base rule (surface, border, radius, padding); hover promotes the border to the accent colour. The **title control** is the exception: it shows the brand mark and stays flat on hover — no fill and no accent ring.
- The filter, assistant and legend **panel tabs** keep their inner border transparent in every state, so the tab blends into the panel and its hover accent never draws the edge where it meets the panel — the highlight stops at the panel rather than ringing the tab. Each tab sits on its panel's **inner edge** and is rotated, so its label reads down the edge, and the filters tab's top follows the assistant tab's bottom, which keeps the assistant tab the upper one of the pair. See the [panel tabs illustration](attachments/panel-tabs.svg).
- The **filter panel** is one column: a head naming it with the count of facets that are on, a **Search** box with its scope under a divider, and the four attribute facets — Kinds, Types, Tags and Status — each a label, its **chips** and a `Select …` button, with **Clear filters** at the foot. A chip is a facet that is on: its label flips include and exclude and its `×` removes it. A facet's list opens as a searchable popover of **wrapping pills** that cycle through none, include (`✓`, filled with the accent) and exclude (`−`, red and struck). See the [filter panel illustration](attachments/filter-panel.svg).
- Groups are translucent, blurred pills that hold related controls.
- Toggle buttons (Labels and Tags) carry their state in `aria-pressed`. The **on** state is the normal label; the **off** state dims the label to a shade only slightly lighter than the button surface, rather than tinting the button fill.
- The title control and the mobile hamburger use the same vertical box model as the nav buttons. The title's brand mark is taller than a text line box, so the title carries a negative block margin that absorbs the excess and keeps every top-bar group the same height.
- The brand *okfy* appears in three forms. The **toolbar title** shows the **node mark**: each of the four letters sits in a filled circle in a node-kind colour — Directory (`#8b93a7`), the Concept colour (the accent, `#5b8def`), File (`#c9a24d`) and Concept type (`#a274d6`) — with the letters in white and short links between the circles in the graph link colour (`#6a7488`). The four nodes sit closer together than before and at slightly uneven heights — the vertical offset stronger than the horizontal — so the strand dips and rises rather than running straight. It is one inline `<symbol>` reused with `<use>`, drawn at 96×32, and it carries no background of its own. The **About panel** prints *okfy* as plain text.
- The **canvas** carries the graph's whole gesture vocabulary. The view is a zoom and an offset, the zoom clamped to `0.02 … 4`: the wheel zooms about the pointer, so the point under it stays put, two fingers pinch about their midpoint and that pinch pans as it zooms, and a drag on empty canvas pans, with the cursor a **grab** that becomes a **grabbing hand** while panning and a **pointer** over a node. Any gesture takes the view over from the **auto-fit**: while a bundle is still loading it **eases** the framing out to include the nodes as they arrive, and it stops for good as soon as the user pans, zooms or drags; an on-demand expansion after that **keeps the view** rather than re-framing it. Toggling **Tags** does re-frame, with the same ease, since it adds a hub per tag and hides the directory ring. **Reset view** re-fits the whole graph and **Reset layout** re-runs the layout; both **ease** into the new framing over about 0.4 s with an ease-in-out curve instead of cutting to it, and a pan, zoom or drag cancels the move. **Hovering** a node highlights it and its direct neighbours while everything else dims, and the tooltip names the node — its label, kind and path, description, tags, link counts and, on a node with neighbours held back, "N of M shown". A **plain click** keeps the node's own action — enter a directory, toggle a tag, load a placeholder, load the next level, else open the preview — and never changes what is drawn; there is no marquee, no multi-select and no keyboard navigation on the canvas. A **drag** pins the node under the pointer and hands it back to the simulation on release, while a **600 ms press and hold** is the second gesture — a deck card on a concept, the expansion dial on a directory or tag. Entering a directory re-roots the graph, re-frames the view and names the path in the toolbar's **Top / Back / Forward** group. See the [graph interaction illustration](attachments/graph-interaction.svg).
- **Node labels** are drawn in **screen space** at a size that tracks the zoom and **tapers** as the canvas is zoomed out — `clamp(11.5 × zoom, 5, 18)` px — so a label stays proportional to its node as the graph shrinks rather than sitting at a fixed size on a tiny one. They fade out between zoom `0.55` and `0.30` and are hidden below that.
- An **expandable node** — a directory or tag hub — carries its expansion state in the ring and the fill: the body is **filled** in its kind colour once any neighbour is shown and **hollow** when none is shown yet, and a **dashed ring** marks neighbours still held back, so a partially expanded node is a filled circle with a dashed ring around it. Its tooltip names the count ("N of M shown"). See the [expansion states illustration](attachments/expansion-states.svg).
- A **press-and-hold** on an expandable node opens the **expansion dial**, a temporary overlay drawn around the node and held above the canvas. It carries **no text**: its four modes are pictograms built from the graph's own vocabulary — a solid node is shown, a dashed ring is held back, an arrowhead is a neighbour appearing, and an extra level of nodes marks the recursive mode — and a mode with nothing to do is drawn faded. Drag to a sector and release to apply it; release in the hub, or press `Escape`, to cancel. It is drawn in the viewer's own palette — the dark theme's variables and the node colours — so the figure reads as the tool does, at **half size** on a desktop and **three-quarters** on a screen under 760px, where it also has to be a touch target; its line weights do not shrink with it. See the [expansion dial illustration](attachments/expansion-dial.svg).
- Legend rows carry horizontal padding, so the hover and selected highlight boxes enclose the swatch, label and count with even space on both sides.
- The **preview** is one reused panel that opens a node's page: a card up to 840 × 940 px, rounded and deep-shadowed, centred over the graph behind a 55 % black scrim, with one header row — back and forward (disabled until there is history), the title and the path sharing a line and both ellipsised, the add-to-deck handle `⋮`, and **Close**. Its body opens with the page's frontmatter as chips, then the rendered Markdown; a text-based image page adds a **Show source** toggle at the end of that row, an image fills the body whole without scrolling, a binary shows its file details as a definition list, and a clip plays on the shared mel spectrogram with one volume control. Only a file, concept or index opens here — a directory or tag hub has no page — and reading a deck reuses the same card with its header controls hidden. See the [node preview illustration](attachments/node-preview.svg).
- Media means the **audio and video** kinds: their `file` nodes take their kind from the extension — audio (mp3, m4a, aac, wav, ogg, oga, opus, flac, weba, aif, aiff) and video (mp4, m4v, webm, ogv, mov, mkv), with a sibling `.vtt` track for captions. None is read into the graph; a clip's bytes are read only when its preview opens, within a byte bound. Audio draws the shared mel spectrogram with the transport over its foot, video uses a plain media element with the browser's own controls, both carry one shared and remembered volume control, and the `.vtt` track is both captions over the clip and a transcript page of its own. See the [media file kinds illustration](attachments/media-kinds.svg).
- The **assistant** is a docked, full-height panel at the right edge, carrying the **Assistant** tab on its inner edge (above the Filters tab) and a **resize** strip on that edge that tints with the accent only near the pointer. Its header names the panel and holds three box-less icon toggles — audio output, microphone and settings — muted when off and the accent when pressed; below it a dismissable **notice** names the host that receives the prompt, the concepts the tools read and the key. The transcript is a column of bubbles — user on `panel-2` with a border, assistant in a light accent, commentary in a stronger accent with a live mel spectrogram and a stop/replay button, tool and notice dashed, and error in the warn tint — and the bubble that is speaking sticks to the top or bottom edge, so it is never pushed out of range. The form carries the prompt with an inline speaker while it speaks, then one row: the model chip, the ring-and-arrow token usage, the budget and Stop/Send, and the list buttons open a searchable model list. Settings replaces the chat, and until the acknowledgement gate is accepted nothing else in it shows. See the [assistant panel illustration](attachments/assistant.svg).
- The **deck of cards** has no panel: the cards float on the right edge, marked only by their shadows, as small paper-like slips that overlap so each shows a header strip and the last card is fully visible. Hovering one repels its neighbours, and two tiny tab chips ride the stack — a **kind chip** above the top card and a **tag chip** under the bottom one — highlighting together while any card is pointed at. A card carries the page screenshot and, on hover, a bare **remove** `×` that reddens at the top right and a sub-deck **expand** chevron at the top left with a round accent highlight; it can be hovered (accent border, deeper shadow, inner glow), current (a solid accent ring for the page open in the preview) or flashing (a fading ring for a card just added). Up to eight decks are kept as separate stacks a gap apart, with accent pills counting the decks scrolled past an edge. A dragged card is a real card following the pointer, and the **drop site** is a separate fixed-size rectangle that is dim outside, lit inside and dashed when a release would start a new deck. The column is a fixed scroll area with no visible scrollbar and a column-height of empty room above and below, so the decks can be dragged or scrolled out of view either way, and its empty space is dragged to scroll rather than reaching the graph. See the [deck of cards illustration](attachments/deck.svg).
- The **full-page view** is a deck read as one stream: opening a card fills the window (no OS fullscreen is requested) with its own top layer, leaving the interface untouched beneath it. Its top bar keeps only the current page's title and path — the history controls, the add-to-deck handle and **Close** are hidden — and a **grabber pill** sits at the top edge. Each decked page is one section, following in deck order in a centred column about 720 px wide, with no visible scrollbar and a hairline between pages. Reading is left by pulling the grabber or the bar down past a short distance, or with `Escape`; the graph shows through as it is pulled, and a shorter pull springs back. See the [full-page view illustration](attachments/full-page.svg).
- The **audio and video previews** reuse the shared surfaces: the audio player draws its rolling spectrogram on a framed canvas — the same mel view the assistant's speech bubbles use — with the **play/pause** button, the **scrubber** and the position read-out laid inline over the foot of the spectrogram, on a soft gradient that keeps them legible. The scrubber is a **fill**: the filled part of the track is the position, with no circular handle, and dragging it scrubs — the playhead follows the pointer and the drag's speed sets the playback speed, rendered as short overlapping, edge-silent grains rather than resampling, so a slow drag is a pitch-preserving slowdown while a fast one is filled with denser grains so it stays a continuous fast-forward, and held at rest the grains keep firing at the fixed head, so the clip is heard infinitely slowed — a granular freeze — rather than going silent (a streamed clip — a large local one, or a served one played from its blob — is not decoded, so its element plays with the rate following the drag instead). Releasing resumes normal playback, and closing the preview stops the player. **Video** renders in a plain media element with the browser's own controls.
- Text selection is off for the interface and on only where text is the content: input fields, the page display (the preview and the deck reading stream) and the assistant's transcript.

# Favicon and mascot

The page targets **modern browsers and OS**. It declares its favicon as a scalable SVG icon in an inline `data:` URI, which keeps the single-file format, since the tool never loads `data:` images from bundle content. Because iOS does not use SVG favicons — for example in bookmarks — it also embeds an ICO as a second inline `data:` URI, and declares `/favicons/favicon.ico` first as a lowest-priority `icon` for clients that ignore the inline `data:` icons. It keeps the **`apple-touch-icon` at the site root**, as `apple-touch-icon.png`, where iOS looks for it, and adds a web app manifest at `/favicons/site.webmanifest` that makes okfy installable, and it omits the fixed-size raster PNG fallbacks. The toolbar shows an **Install** button once the browser offers installation. The CSP allows `manifest-src 'self'` and `worker-src 'self'` for the manifest and the optional service worker, `img-src 'self' blob: data:` so the manifest icons and screenshot can load while bundle images still come only from blob URLs, and `media-src blob:` so a previewed video plays from a blob URL of its own bytes. See [Favicon](favicon.md) for how the `icon` link relation works, and [Installable web app](../interface/installable-web-app.md) for the install surface. The figure is the project's **mascot**: a stick figure in a victory pose whose nodes follow the graph vocabulary — the torso is the root directory, the head, shoulder, elbows and hands are concepts, the knees and feet are files, and each arm and leg is drawn as two links. It is drawn inline in the About panel, and kept as [`attachments/favicon.svg`](attachments/favicon.svg) for documentation.[^source]

In those two panels the figure starts in a fixed pose and alternates on a 10-second timer: it holds the pose, then releases it and lets physics run — the same velocity-Verlet force layout the graph uses (softened repulsion, link springs, a decaying temperature), so the joints relax into a laid-out arrangement at the graph's rapid pace — and then forcibly drags the joints back into the fixed pose. The cycle restarts when a panel becomes visible. Joint rest positions come from the markup; the link topology and the physics weights live in the script. A hidden panel is skipped, and `prefers-reduced-motion` leaves the figure static.

# Accessibility

State is carried by attributes, not colour alone where it matters: `aria-pressed` on the toggles, `aria-expanded` on the title, labelled inputs, and a reduced-motion fallback for the loading spinner and the mascot figure. Panels are reachable by keyboard, and external links open with `rel="noopener noreferrer"`.[^source]

# Guidance

Keep the single-file, dependency-free approach and reuse the CSS custom properties instead of ad-hoc colours. Prefer expressing component state with ARIA attributes so the visual cue follows the semantics. Update this concept when the theme, layout, components or accessibility cues change.
