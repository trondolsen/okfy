## Scope

The review covers the handling of untrusted Markdown bundles, loading of local files, URL containment, HTML rendering, images and PDF metadata. It does not include a full penetration test, server configuration, access control on the host, or a formal compliance assessment.

The original assessment was static. Subsequent changes were reviewed statically, including separate reviews of the renderer, PDF handling and integration. Browser events, actual network traffic, memory use and performance have not been verified by running.

## Findings and fixes

The severities describe the risk before the fixes. "Implemented" means the code has changed, not that the fix has been confirmed effective in a browser.

| ID | Severity | Original finding | Implemented fix |
| --- | --- | --- | --- |
| A1 | High | Markdown placeholders could place generated HTML into attributes and create executable event attributes. | `renderInline` and `renderMarkdown` use context-aware parsing with escaping at text and attribute output. HTML placeholders have been removed. The CSP forbids inline event attributes. |
| A2 | Medium | URL normalization, image fallback and redirects could trigger requests outside the selected bundle root. | `normalizeLinkPath`, `validBundlePath`, `bundleUrl` and `urlWithinBundle` constrain final URLs. `trackedFetch` rejects redirects and omits credentials. Images load through the same checks and are shown only from blob URLs. |
| A3 | Medium | Forged, self-referential placeholders could cause exponential growth in the rendered HTML. | The placeholder mechanism has been removed. The renderer has limits on input, output, nesting and search work. Control characters are replaced without joining together new syntax. |
| A4 | Medium | PDF streams were decompressed and buffered before the size limit was checked. | `inflateDeflate` reads decompressed bytes with `readBoundedStream`. All included object streams and delimiters share one limit. Oversized streams are discarded without keeping partial text. |
| A5 | Medium | HTTP responses were size-checked after buffering; file, graph and total budgets were incomplete; fetch slots were released at the response headers. | Response streams are read with a byte limit and timeout. File, directory, graph, reference and image limits are enforced. Parallel text and image reads reserve capacity. The fetch slot is held through body reading or cancellation. |
| A6 | Low | Blob URLs were reused by file path across local bundles and were not released. | The cache is tied to the current blob. URLs are revoked on replacement and bundle switch. Preview history and pending image lookups are reset on a real bundle switch. |

### A1: Attribute injection

A harmless marker example from revision 1 was:

```markdown
[click](![ onclick=document.title=1337 x=](data:,))
```

The old renderer could reconstruct an image fragment inside the link's `data-link` attribute. The fragment's quote character closed the attribute and turned `onclick` into an actual HTML attribute. Forged U+0001 placeholders also enabled an automatic `onerror` variant.

Revision 2-draft parses raw syntax and writes escaped values directly into the correct context. Link labels cannot create nested links or images. Images are rendered first with `data-embed`, without `src`; validated loading later sets a blob URL through the DOM API. External links are validated separately and use `noopener noreferrer`.

### A2: URL and network bounds

The bundle root is used consistently for crawling, expansion, images and metadata. Server file paths are kept relative to the declared root; they are not changed to a common prefix in the loaded file set.

The following are rejected or normalized before loading:

- paths that cross the bundle root
- backslashes, control characters and URI schemes in internal references
- ambiguous encoded separators and double encoding
- request URLs with credentials, query or fragment
- other origins and paths outside the final bundle root

HTTP requests use `credentials: "omit"` and `redirect: "error"`. The CSP allows `blob:` images plus the page's own inline `data:` favicon; direct network images and the raw URL fallback have been removed. Local bundles cannot fetch images over the network.

The crawler shares destination parsing with the renderer, so that, among other things, angle-bracket destinations and balanced parentheses are handled the same way. Alternative path links are tried on HTTP 404, not on redirects, access errors or other loading failures.

### State and integration

As part of the fixes, the following is also ensured:

- Graphs are built in private data structures before the new state is published.
- A rejected expansion does not change the installed file set; new file loads are rolled back.
- Local attachments can be materialized even if the file is already counted in the budget.
- Asynchronous previews and metadata callbacks check the render ID and bundle generation.
- Preview history contains the bundle generation, so old history entries do not point into a new bundle.
- Full loading uses a request number, so an older HTTP result does not replace a newer selected bundle.
- Header-only metadata requests cancel the body without buffering it, also when the server ignores Range.

## Limits in revision 2-draft

| Area | Limit |
| --- | --- |
| Text file | 512 KiB before full buffering |
| Bundle | 2,000 files and 32 MiB of text bytes |
| Directory entry / graph node | 8,000 |
| Local directory depth | 12; deeper trees are rejected |
| Stored file path | 2,048 characters and 24 path segments |
| Graph links | 20,000 |
| References from a Markdown body | 256 per file; frontmatter sources have their own limit of 256 |
| Tags | 64 per file, at most 256 characters and 16 namespace segments per tag |
| HTTP | 4 concurrent requests through body reading; at most 64 pending; 30-second timeout after a slot is granted |
| Crawling / new expansion attempts | At most 2,000 URLs per crawl and 2,000 expansion attempts per bundle |
| Markdown preview | 512 Ki characters in, 2 Mi characters of HTML out, nesting 24 and bounded search work |
| Images | 8 MiB per image, 16 MiB cache incl. capacity reservations, 64 images per preview |
| Local PDF | Whole files up to 16 MiB; otherwise 2 MiB windows from the start and end |
| HTTP PDF | 512 KiB per start/end response, regardless of whether the server honors Range |
| PDF decompression | 8 MiB total object-stream text incl. delimiters; at most 200 streams attempted |

The limits apply to raw content volumes and the records in the structures described. They are not a guarantee of a particular maximum heap use or CPU use in the browser.

## Behavior changes

- Bundles that require authentication cookies, HTTP credentials or redirects no longer load through these requests. Use suitable static hosting; do not remove the URL controls to work around this.
- External images, data URIs and manually specified blob URIs in Markdown are not shown. Put the images in the bundle and use internal references.
- Images that are rejected or missing are replaced with alternative text. A preview of very many images is limited to 64.
- A large HTTP PDF on a server without Range support does not get an unlimited full-download fallback; PDF metadata may therefore be unavailable.
- Oversized local text files are skipped. Bundle, directory and graph limits can reject loading or growth with an error message.
- The renderer is still a bounded, dependency-free Markdown renderer, not a full CommonMark implementation. Pathological input can produce a safety notice instead of a preview.

## Verification

59 regression tests are in [`test/unit/security.test.cjs`](../../test/unit/security.test.cjs). They use only built-in Node modules and read actual helper functions from the HTML file, without test exports in the production code.

The tests cover, among other things, the original injection and amplification payloads, ordinary Markdown, URL containment, streaming and cancellation, concurrency slots, PDF decompression, aggregate reservations, local attachments, rejected graph growth and bundle switching. The network and parts of the DOM/layout startup are mocked.

Run from the repository root with the Node start script in Podman:

```sh
bash tools/node-cli/run.sh --workdir . -- --test test/unit/security.test.cjs
```

**Result from the user-supplied TAP output:** 59 tests passed, 0 failed, 0 cancelled, 0 skipped and 0 TODO; total runtime 136.884823 ms. The test that compiles the entire actual HTML script also passed. The result is recorded from the output the user shared, not from a new run performed by the agent. The Node version and runtime environment are not stated in the output.

The editor's diagnostics for the HTML file and the test file reported no errors or warnings. The passing tests use a mocked network and parts of the DOM/layout startup; actual browser behavior, CSP enforcement and network traffic are still not verified.

The following browser checks remain:

- [ ] The marker payloads create no event attributes and do not change the document title.
- [ ] The network panel shows no requests outside the bundle root or forwarded redirects.
- [ ] Local images work; external/data/raw blob images trigger no loading.
- [ ] Normal crawling, depth limiting, local attachments, SVG images, footnotes and navigation work.
- [ ] Oversized streams, PDFs, decompression results and bundles are rejected within the limits.
- [ ] Switching bundles during active requests shows no earlier images, text or metadata.
- [ ] A graph-limit failure leaves the previous bundle usable and allows a new attempt once the cause is removed.

## Residual risk and further control

- Inline application scripts are still allowed to preserve a single HTML file. `script-src-attr 'none'` is additional protection against event attributes, but its support and effect must be verified in the target browsers. A script hash could be considered as further hardening.
- Image limits bound compressed bytes, not the number of decoded pixels. The browser's image and SVG decoders remain part of the trust base.
- Streaming bounds retained content, but the browser or the decompression engine can allocate a chunk before JavaScript has time to check it.
- URL containment controls network addresses, not the server's mapping to files. Symlinks, internal rewrites and misconfigured publishing must be checked on the server.
- Prefer a dedicated static origin without sensitive application routes. A combined byte limit is not a promise of low memory use for all allowed graphs.
- The regression tests passed according to the user-supplied result. Release approval should still wait until the relevant browser checks have been performed.
